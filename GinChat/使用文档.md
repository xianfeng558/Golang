# GinChat 使用文档

这是一个用 Go 写的单机聊天室。浏览器只访问一个进程：页面和表单走 HTTP，聊天走 WebSocket。用户、好友、群在 MySQL 里，在线状态和私聊记录在 Redis 里。

下面这些已经在本机跑通：打开登录页和注册页、注册、登录、错误密码、修改资料、加好友、建群、加群、两人私聊、群消息、上传图片、错误令牌被拒绝。MySQL 用的是 `config/app.yml` 里的 `root` / `root`。`go test ./...` 会把上面这条链路再跑一遍。

## 1. 这是什么架构

只有一个进程。它自己听 HTTP，也自己保管所有 WebSocket 连接。没有第二个服务，也就没有服务发现。

```text
浏览器
  → Gin（页面、注册、登录、好友、群、上传）
    → service（取出表单字段，决定成功还是失败）
      → models（写 MySQL，或把消息交给某条 WebSocket）
        → MySQL / Redis
```

聊天页另外开一条长连接：

```text
浏览器 WebSocket  /chat?userId=..&token=..
  → models.Chat 核对令牌，把这条连接放进内存表
    → 对方发来消息时，写进这条连接
    → 同时把私聊原文放进 Redis
```

同一时刻，一个用户在这个进程里只有一条连接。后连上的会替换先连上的。换一台机器再跑一个进程，它们之间靠 UDP 把消息广播出去；绑不上 UDP 时，这一台机器上的聊天不受影响。

## 2. 目录是干什么的

```text
D:\golang\GinChat
├── main.go            读配置、连数据库、听端口
├── config/app.yml     MySQL、Redis、端口、心跳
├── router/app.go      URL 和函数的对应关系
├── service            从 HTTP 请求里取值，调用 models
├── models             表、好友、群、WebSocket
├── utils              配置、数据库、密码摘要、JSON
├── views              登录、注册、聊天页
├── index.html         登录页，在项目根目录
├── asset              页面用到的 css、js、图片
├── docs               swag 生成的接口说明
├── sql/init_ginchat.sql  给人看的表结构，启动时不用手工执行
├── flow_test.go       注册到收消息的整段自测
└── 使用文档.md
```

`release/` 是以前打包出去的一份静态资源和 exe。`go run` 用的是根目录的 `asset` 和 `views`，不读 `release`。

| 目录或文件 | 作用 |
| --- | --- |
| `main.go` | 按顺序完成配置、MySQL、建表、Redis、UDP、心跳清理，然后听端口 |
| `config/app.yml` | 本机地址和超时。改完要重新 `go run`，进程只在启动时读一次 |
| `router` | 哪个路径调用哪个函数 |
| `service` | HTTP 层。登录注册用小写 JSON，好友和群用大写 JSON |
| `models` | 真正读写 MySQL 和 Redis，并保管 WebSocket |
| `utils` | 所有业务共用的连接和响应 |
| `views` + `index.html` | 浏览器看到的页面 |
| `docs` | 由注释生成。改接口说明要改 `.go` 里的 `@Router`，再执行 swag |

## 3. 每种文件是什么

安装 Go 时已经带上标准库。这个项目额外用到的 Gin、GORM、Redis、WebSocket，记在 `go.mod` 里。执行 `go run` 或 `go test` 时自动下载到本机模块缓存，一般在 `C:\Users\<用户名>\go\pkg\mod`，不放进项目目录。

| 文件 | 是什么 |
| --- | --- |
| `.go` | 人写的 Go 源码 |
| `.mod` | 模块名字和依赖清单，作用接近 PHP 的 `composer.json` |
| `.sum` | 依赖包的校验和，用来确认下载内容和上次一致 |
| `.yml` | 数据库、Redis、端口 |
| `.html` | 页面。带 `{{define}}` 的是可以被别的页面嵌进去的一块 |
| `.sql` | 表结构的阅读稿。真正建表的是启动时的 `AutoMigrate` |
| `docs/docs.go` | swag 生成的文件，不要手改 |

`go.mod` 第一行的 `module ginchat` 是这个文件夹的名字。代码里的 `ginchat/models` 就是 `models` 目录。

## 4. 一条私聊消息怎么走

先有两个已经登录的用户。聊天页在 `views/chat/foot.html` 里连接：

```text
ws://127.0.0.1:8080/chat?userId=3&token=登录返回的Identity
```

`token` 必须等于这个用户 `user_basic.identity` 里的值。对不上，连接升级会被拒绝，HTTP 状态是 401。

用户 3 给用户 4 发一句「你好」时，页面发出的 JSON 大致是：

```json
{"userId":3,"TargetId":4,"Type":1,"Media":1,"Content":"你好"}
```

服务端接着做这些事：

```text
用户 3 的 WebSocket
  |  Type=3 只刷新心跳，不往下走
  |  Type=1 私聊：找到用户 4 的连接，把这段 JSON 原样写回去
  |  同时 ZADD 到 Redis 键 msg_3_4
  v
用户 4 的页面 onmessage 收到同一段 JSON
```

键名把两个 ID 从小到大排。3 看 4 的记录，和 4 看 3 的记录，是同一把钥匙。分数是发送时的毫秒时间，所以后发的排在后面。

群消息是 `Type=2`，`TargetId` 是群 ID。服务端查出群里的人，跳过发送者，再写到其他人的连接上。群消息只负责送达，不写进两人的私聊记录，避免打开单聊时混进群里的内容。

转发时用的是浏览器发来的那一段字节。如果在服务器里重新编一次 JSON，字段会变成 `UserId`，页面读的是 `data.userId`，昵称和内容就对不上。

## 5. 环境

需要本机已经有：

- Go 1.21 或更新。当前编译用的是 1.25，`go.mod` 写的是 1.17
- MySQL，默认 `127.0.0.1:3306`，账号 `root` / `root`
- Redis，默认 `127.0.0.1:6379`，没有密码

工作目录必须是 `D:\golang\GinChat`。配置路径、模板、静态文件都是相对这个目录写的。

数据库不用手工建。进程启动时会执行 `CREATE DATABASE IF NOT EXISTS ginchat`，再用 GORM 的 `AutoMigrate` 建出 `user_basic`、`contact`、`communities`、`message`、`group_basic`。`AutoMigrate` 会补列，不会删列，也不会改已有数据。

`sql/init_ginchat.sql` 是这份表结构的阅读稿，方便对着模型看列名。

下面这些不准备也能聊天：

| 组件 | 不准备时会怎样 |
| --- | --- |
| 阿里云 OSS | 上传写到本机 `asset/upload`，接口照常返回路径 |
| UDP 3001 | 日志里会写监听失败。同一台机器上的两个浏览器仍然能聊 |
| Swagger 页面 | 只影响 `/swagger/index.html`，业务接口不依赖它 |

## 6. 启动

一个终端就够。停在那里不要关。

```powershell
cd D:\golang\GinChat
go run .
```

看到这几行再打开浏览器：

```text
config loaded ...\config\app.yml
MySQL ready ginchat
Redis ready 127.0.0.1:6379
udp broadcast on 3001
GinChat listening :8080
```

`udp broadcast on 3001` 表示局域网广播也起来了。没有这一行、只有「单机聊天仍可用」，HTTP 和 WebSocket 已经可以测。

| 看什么 | 地址 |
| --- | --- |
| 登录 | http://127.0.0.1:8080/ |
| 注册 | http://127.0.0.1:8080/toRegister |
| 接口说明 | http://127.0.0.1:8080/swagger/index.html |
| 聊天页 | 登录成功后页面自己跳到 `/toChat?userId=..&token=..` |

这个仓库里的 goshop 商品 RPC 占着 `8082`。GinChat 因此听 `8080`，写在 `config/app.yml` 的 `port.server`。要换端口就改这一行，然后重新 `go run`。

如果日志是 `bind: Only one usage of each socket address`，说明 8080 上一次的进程还在。关掉那个终端，或者在任务管理器里结束对应的进程。

MySQL 或 Redis 连不上时，进程会直接退出，并写明是哪一个失败。改 `config/app.yml` 的 `user`、`pwd`、`addr` 后再启动。这个项目没有把 YAML 嵌进可执行文件，但进程只在启动时读它，所以改完文件不重启仍然不生效。

重复自测：

```powershell
cd D:\golang\GinChat
go test ./...
```

`TestChatFlow` 会自己拉起路由，走完注册、登录、好友、群、私聊、历史消息、上传和错误令牌。它需要本机 MySQL 和 Redis，和 `go run` 的要求一样。

## 7. 亲手调一遍

注册。确认密码用字段 `Identity`，因为注册页的输入框绑的是这个名字。`repassword` 也可以。

```powershell
curl.exe -X POST -d "name=ada&password=pass123&Identity=pass123" http://127.0.0.1:8080/user/createUser
```

成功时 `code` 是 `0`。响应里没有密码和盐。用户名再注册一次会得到「用户名已注册！」。

登录。看 `data.ID` 和 `data.Identity`。后面的聊天连接要用这两个值。

```powershell
curl.exe -X POST -d "name=ada&password=pass123" http://127.0.0.1:8080/user/findUserByNameAndPwd
```

密码不对时 `code` 是 `-1`，这是预期的：

```powershell
curl.exe -X POST -d "name=ada&password=nope" http://127.0.0.1:8080/user/findUserByNameAndPwd
```

再注册一个 `bob`，用 ada 的 ID 加他。好友、群这组接口的成功标志是大写的 `Code`。

```powershell
curl.exe -X POST -d "name=bob&password=pass123&Identity=pass123" http://127.0.0.1:8080/user/createUser
curl.exe -X POST -d "userId=这里填ada的ID&targetName=bob" http://127.0.0.1:8080/contact/addfriend
curl.exe -X POST -d "userId=这里填ada的ID" http://127.0.0.1:8080/searchFriends
```

建群、按群名加入、再看群列表：

```powershell
curl.exe -X POST -d "ownerId=ada的ID&name=周末小组&desc=测试" http://127.0.0.1:8080/contact/createCommunity
curl.exe -X POST -d "userId=bob的ID&comId=周末小组" http://127.0.0.1:8080/contact/joinGroup
curl.exe -X POST -d "ownerId=ada的ID" http://127.0.0.1:8080/contact/loadcommunity
```

修改资料可以只提交 ID、昵称和头像，手机和邮箱空着也能成功：

```powershell
curl.exe -X POST -d "id=ada的ID&name=ada&icon=/asset/images/avatar0.png" http://127.0.0.1:8080/user/updateUser
```

打开两个浏览器窗口，分别登录 ada 和 bob，从好友列表点进会话。一边输入文字，另一边会收到。私聊历史可以用：

```powershell
curl.exe -X POST -d "userIdA=ada的ID&userIdB=bob的ID&start=0&end=9&isRev=false" http://127.0.0.1:8080/user/redisMsg
```

返回的 `Rows` 是字符串数组，每一项是当时发出的 JSON。`isRev=false` 表示从新到旧。

错误令牌连不上聊天，下面这一行得到 401：

```powershell
curl.exe -o NUL -w "%{http_code}" "http://127.0.0.1:8080/chat?userId=1&token=bad"
```

## 8. 项目里的技术，分别是什么

### Gin

HTTP 框架。`r.POST("/user/createUser", service.CreateUser)` 把路径和方法对上。处理函数拿到 `*gin.Context`，用 `FormValue` 读表单，用 `c.JSON` 写响应。

页面有两条路。登录页和注册页用 `template.ParseFiles` 自己解析，因为登录页 `index.html` 放在项目根目录，不在 `views` 里。聊天页也用同一套解析，好把 `views/chat` 里带 `{{define}}` 的几块拼起来。静态文件由 `r.Static("/asset", "asset/")` 提供。

模板解析失败时返回 500 和错误文本。以前这里直接 `panic`，一个打不开的页面会把整个进程带走。

### WebSocket

`gorilla/websocket` 把一次普通 HTTP 请求升级成长连接。升级成功之后，这条连接不再走 Gin 的返回值，而是由两个协程负责：一个读，一个写。

读循环看到 `Type=3` 就当心跳。页面每 10 秒发一次，内容是「心跳」。其它消息交给 `dispatch`。

写的时候不直接在读循环里 `WriteMessage`。消息先进入 `DataQueue`，由写协程取出再写。这样读循环不会被一次写堵住。队列最多 50 条，满了就丢掉新的并打日志。

连接关掉时用 `sync.Once` 保证只清理一次：从内存表删掉、关掉通知通道、删掉 Redis 里的在线标记、关闭连接。

`CheckOrigin` 现在固定返回 true，本机用不同端口的页面也能连。这只适合学习，正式环境应按页面来源判断。

### Viper

`utils.InitConfig` 读 `config/app.yml`。业务代码用 `viper.GetString("mysql.host")` 这种写法取值。

YAML 里的 `port: 3306` 不带引号，`GetString` 仍然能得到 `"3306"`。整数超时用 `GetInt`。

### GORM 和 MySQL

GORM 把结构体当成表。`gorm.Model` 带来 `ID`、`CreatedAt`、`UpdatedAt`、`DeletedAt`。删除用户是软删除：行还在，之后的查询会滤掉 `deleted_at` 不为空的行。

驼峰字段会变成下划线列名，例如 `PassWord` 变成 `pass_word`。`TableName()` 用来指定真实表名。群表是 `communities`，关系表是 `contact`，不要让 GORM 自己加复数。

`LoginOutTime` 上的 `gorm:"column:login_out_time"` 是因为默认会把 `Out` 拆成不好读的列名，这里把列名写死。

好友要插两行：A 的名单里有 B，B 的名单里也有 A。这两次插入在同一个事务里。建群也是：先插入群，再把群主写成一条 `type=2` 的关系。事务对象是 `tx`，插入必须打在 `tx` 上。以前 `Begin` 之后却用全局 `DB.Create`，回滚不会生效。

`Find` 用来做「可能没有」的查询。`First` 在没有行时会记一条 record not found，注册一个新用户也会看起来像出错。

### Redis

三件事：

| 键 | 值 | 什么时候写 |
| --- | --- | --- |
| `online_用户ID` | 连接的远端地址 | WebSocket 连上时，心跳时续期。时长来自 `timeout.RedisOnlineTime`，默认 4 小时 |
| `msg_较小ID_较大ID` | 有序集合，成员是私聊 JSON | 只在 `Type=1` 时写入 |
| `websocket` | 发布订阅频道 | 只有演示接口 `/user/sendMsg` 使用，聊天页不走它 |

投递前会看收件人是不是在本进程的内存表里，以及 `online_` 键还在不在。人在另一台机器上时，本进程没有那条连接，消息仍然可以靠 UDP 到达对方进程，再由对方写进自己的连接。

`/user/redisMsg` 的 `start` 和 `end` 是有序集合的下标，不是用户 ID。页面第一次取 0 到 9。

### MD5

`utils/md5.go` 做两件事。

密码是 `Md5Encode(明文 + 盐)`，盐是注册时生成的 6 位数字，存在 `salt`。登录时用同样的盐再算一次，和库里的摘要比较。MD5 很快，不适合保护真实密码。这里只为了看懂「盐 + 摘要」这条链路。正式项目的密码应使用 bcrypt 一类算法。

登录令牌是 `MD5Encode(用户ID-当前纳秒)`，写成大写，存在 `identity`。它不是密码。两个用户同一秒登录也不会得到同一个令牌。页面把这个值放进 `/toChat` 的 `token`，WebSocket 再拿来核对。

响应里用 `json:"-"` 去掉了 `PassWord` 和 `Salt`，注册和登录的 JSON 不会带出摘要。

### 两套 JSON

历史页面已经按这两种形状写好了，所以接口保持不变。

登录、注册、改资料、用户列表用小写：

```json
{"code":0,"message":"登录成功","data":{"ID":7,"Name":"ada","Identity":"..."}}
```

好友、群、上传、历史消息用大写：

```json
{"Code":0,"Msg":"添加好友成功","Data":0,"Rows":null,"Total":null}
```

列表把数组放在 `Rows`。好友列表的 `Total` 是数量，群列表的 `Total` 是「查询成功」。历史消息的 `Rows` 才是消息数组。以前历史消息被放进了 `Total`，和字段名的意思相反，页面已经改成读 `Rows`。

### Swagger

函数上方的 `// @Router /user/createUser [post]` 是给 swag 看的注释。执行下面的命令会重写 `docs/`：

```powershell
cd D:\golang\GinChat
go run github.com/swaggo/swag/cmd/swag@v1.8.2 init
```

浏览器打开 http://127.0.0.1:8080/swagger/index.html 。`docs/docs.go` 不要手改，下一次生成会覆盖。

### UDP 广播

`models.StartUDP` 监听 `port.udp`（3001），并把每条业务消息广播到 `255.255.255.255`。另一台机器上的进程如果也在听 3001，就会收到并再投递给自己的在线用户。

本机广播会把自己发出去的包又收回来。`dispatch` 用这段内容的 MD5 记一分钟，第二次看见就丢掉，避免同一个人收到两遍。

监听或拨号失败只打日志。单机的两个浏览器不经过 UDP。

### 定时清理

`utils.Timer` 先等 `DelayHeartbeat` 秒（3），之后每 `HeartbeatHz` 秒（30）看一遍连接。`HeartbeatMaxTime` 的单位是秒，直接和上次心跳的 Unix 秒相加。默认 60 秒没有心跳就关闭连接。

页面 10 秒跳一次，正常情况下不会被清掉。把浏览器断网超过一分钟，这条连接会被关掉，Redis 里的 `online_` 键也会删掉。

### 阿里云 OSS

默认上传是 `UploadLocal`，文件在 `asset/upload`，返回 `/asset/upload/文件名`。文件名由时间生成，后缀只保留字母和数字，避免用上传者原来的路径写出目录外面。

`UploadOSS` 留在 `service/attach.go`，路由没有调用它。`config/app.yml` 里的 Endpoint 和密钥是空的。要改走阿里云时再填写，并把 `Upload` 函数里的调用换成 `UploadOSS`。密钥留空时接口返回「未配置阿里云 OSS」，进程不会退出。

如果这台机器上的旧配置曾经写过真实的 AccessKey，建议在阿里云控制台禁用那一对。当前文件里已经没有密钥。

## 9. 建议阅读顺序

手写的 `.go` 用中文注释说明这个类型或函数在业务里做什么。`docs/docs.go` 是 swag 生成的，阅读时跳过，也不要手改。

1. `config/app.yml`

## 10. 读代码时会反复见到的 Go 写法

- `func (node *Node) Heartbeat(...)`：给结构体定义方法。`node` 是接收者，类似别的语言里的 `this`，名字要自己起。用指针，改的是原来的那条连接，不是一份拷贝。
- `func CreateUser(user *UserBasic) error`：参数用指针，插入之后调用方才能看到数据库生成的 ID。
- `go recvProc(node)`：启动一个协程。读连接、写连接、UDP、心跳清理都在协程里，避免堵住 `main`。
- `select { case <-node.done: ... case data := <-node.DataQueue: ... }`：等多件事里先发生的那一件。`done` 被关掉时，写协程退出。
- `defer sub.Close()`：函数退出时一定执行，用来关掉 Redis 订阅和上传的文件。
- `sync.RWMutex`：多个协程可以同时读 `clientMap`，写的时候独占。查在线用户用读锁，登记和删除用写锁。
- `sync.Once`：同一条连接的清理只做一次。读协程和定时器可能同时发现它该关了。
- `json:"-"`：这个字段仍在结构体里，编码成 JSON 时跳过。
- `log.Fatal`：打印错误并让进程退出。配置或数据库根本不可用时才会这样。

## 11. 常见现象

| 现象 | 原因 |
| --- | --- |
| `MySQL ready ginchat` 之后刷出很多 SELECT | 正常。GORM 正在对一下表结构，之后每条 SQL 也会打出来 |
| `udp broadcast on 3001` | 正常。局域网广播已打开 |
| `udp 监听失败，单机聊天仍可用` | 3001 被占用或当前网络不能广播。本机聊天继续 |
| `bind: Only one usage of each socket address` | 8080 或 3001 上还有旧进程 |
| 打开 8082 没有聊天页 | 8082 是 goshop 商品服务。聊天页在 8080 |
| 注册返回「用户名已注册」 | 这个名字已经在 `user_basic` 里 |
| 登录返回「密码不正确」 | 预期的失败路径，`code` 为 -1 |
| 聊天连接 401 | `token` 不是这个用户当前的 `Identity`。重新登录，用新的值 |
| 改了 YAML 不生效 | 进程只在启动时读配置，需要重新 `go run` |
| 详情或登录里的时间带 `+08:00` | 本机时区。列本身是 datetime |
| 单聊历史里没有群消息 | 群消息只投递，不写 `msg_` 键 |
| Swagger 和页面行为不一致 | 改了 `@Router` 之后要重新执行第 8 节的 swag 命令 |

账号、Redis 地址、端口和心跳都在 `config/app.yml`。学习时改这个文件，不要把地址再写回业务函数里面。

## 12. 补上的好友申请

`/contact/addfriend` 仍然马上成为好友，聊天页不用改。另外三条接口用来讲「申请和关系分开」：

| 路径 | 作用 |
| --- | --- |
| `POST /contact/apply` | 表单 `userId`、`targetName`、`remark`。写入 `friend_apply`，状态 0 |
| `POST /contact/applyList` | 表单 `userId`。返回发给这个人的待处理申请，列表在 `Rows` |
| `POST /contact/applyReply` | 表单 `userId`、`applyId`、`accept`。`accept=1` 时在一个事务里写成双向好友 |

已经是好友、重复的待处理申请、自己加自己，都不会插入。只有被申请人能处理。表注释在 `sql/init_ginchat.sql`。

`go test ./...` 会多注册第三个人，走一遍申请、重复申请失败、同意之后出现在好友列表。需要本机 MySQL 和 Redis。
