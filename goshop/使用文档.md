# GoShop 使用文档

这是一个用 Go 写的迷你电商。它拆成了用户、商品、购物车、订单、支付五个服务。拿它入门，目标不是把每一行都背下来，而是看懂：一个请求从浏览器进来，怎么穿过 HTTP 网关，找到另一个进程里的函数，再落到 MySQL 或 Redis。

下面的接口已经在本机跑通：登录、商品列表、商品详情、加入购物车。MySQL 账号用的是各服务 `config` 目录里的 `root` / `root`。

## 1. 这是什么架构

五个服务各自是一个进程。浏览器只访问旁边的 HTTP 网关，网关再按名字调用另一个进程里的函数。数据落在 MySQL 和 Redis 里。

每个业务服务内部是同一套四层。目录名在 Go 里叫 package：

```text
浏览器
  → client（Gin，HTTP 网关）
    → handler（RPC 入口，收请求、填响应）
      → domain/service（业务层，大多只是把调用交给 repository）
        → domain/repository（真正写 SQL、读写 Redis）
          → domain/model（表结构，GORM 靠它建表）
            → MySQL / Redis
```

服务之间不写死 IP。`main.go` 启动时用名字注册自己，例如 `shop-user`、`shop-product`。调用方只说这个名字。本机没有 Consul 时，用 mDNS 在本机互相发现，日志里会看到 `Registry [mdns]`。

一次加购会穿过三个服务：购物车网关先问用户服务「登录了吗」，再问商品服务「库存够不够」并减库存，最后让购物车服务插入一行。完整调用写在第 4 节。

## 2. 目录是干什么的

```text
D:\golang
├── go.work                 把下面几个模块放在一次编译里
└── goshop
    ├── common              五个服务共用：配置、MySQL、Redis、JSON、追踪、监控
    ├── compat/microcmd     补 go-micro 删掉的一个小包，业务不用改
    ├── user-service        登录、保存令牌          RPC 8081，HTTP 8088
    ├── product-service     商品、规格、库存        RPC 8082，HTTP 8087
    ├── shoppingCart-service 购物车、算价           RPC 8084，HTTP 6668
    ├── trade-order         订单                    RPC 8085，HTTP 6669
    ├── payment-service     支付宝 / PayPal         HTTP 8086
    ├── README.md
    └── 使用文档.md
```

`go.work` 告诉 Go：`common` 和五个服务在同一台电脑上一起开发，公共库用本地的 `goshop/common`，不必再从网上拉一份旧的。

每个业务服务里面的文件夹含义相同：

| 目录 | 作用 |
| --- | --- |
| `main.go` | 组装配置、数据库和 handler，然后监听端口 |
| `config` | 本机 MySQL、Redis 的 JSON。改完要重新 `go run`，因为文件被编译进程序 |
| `proto` | 服务之间的接口合同，以及由它生成的 Go 代码 |
| `handler` | 收到 RPC 请求，填写响应 |
| `domain/service` | 业务层，这里大多只是把调用交给 repository |
| `domain/repository` | 真正写 SQL、读写 Redis |
| `domain/model` | 表结构，GORM 靠它建表 |
| `client` | HTTP 网关。浏览器访问这里，再由它去调用 RPC |

两处容易看混：

- `product-service/common` 是商品服务自己的一份 JSON 小工具，和仓库根上的 `goshop/common` 不是同一个包。
- `product-service/domain/model/user.go` 没有被商品服务用到，是课程拷贝用户模型时留下的，读商品流程可以跳过。

## 3. 每种文件是什么

Go 没有一个必须先下载的总框架。安装 Go 时已经带上标准库。这个项目额外用到的 Gin、GORM、go-micro、Redis 客户端，记在各自的 `go.mod` 里，执行 `go run` 或 `go build` 时自动下载到本机模块缓存，一般在 `C:\Users\<用户名>\go\pkg\mod`，不放进项目目录。

| 文件 | 是什么 |
| --- | --- |
| `.go` | 人写的 Go 源码 |
| `.mod` | 这个目录的模块名字和依赖清单，作用接近 PHP 的 `composer.json` |
| `.sum` | 依赖包的校验和，用来确认下载内容和上次一致 |
| `.proto` | 人写的接口合同：有哪些字段、能调用哪个方法 |
| `.pb.go` | 由 `.proto` 生成的数据结构，不要手改 |
| `.pb.micro.go` | 由 `.proto` 生成的 RPC 客户端和注册函数，不要手改 |
| `.json` | 数据库、Redis 的地址和账号 |
| `.md` | 说明文档 |
| `go.work` | 没有后缀。把多个模块放在同一次编译里 |

`go.mod` 第一行的 `module` 是这个文件夹的名字，别的服务用这个名字来 import。例如 `goshop/common/go.mod` 的模块名是 `git.mashibing.com/msb_47094/shopping-comm`，五个服务都 import 这个路径。

## 4. 一条加购请求怎么走

```text
浏览器
  |  GET http://127.0.0.1:6668/increase     请求头 Uuid: 2
  v
购物车 HTTP 网关（Gin）
  |-- RPC shop-user.GetUserToken     问 Redis：这个用户登录了吗
  |-- RPC shop-product.ShowProductDetail
  |-- RPC shop-product.ShowDetailSku  看库存够不够
  |-- RPC shop-product.UpdateSku      先把库存减掉
  |-- RPC shop-cart.AddCart           往 shopping_cart 插一行
  v
JSON 回到浏览器
```

服务之间不写死 IP。每个 RPC 进程启动时用名字注册自己，例如 `shop-user`、`shop-product`。调用方只说名字。本机没有 Consul 时，go-micro 用 mDNS 在本机找对方，日志里会看到 `Registry [mdns]`。

## 5. 环境

需要本机已经有：

- Go 1.21 或更新。当前工作区写的是 1.25
- MySQL，默认 `127.0.0.1:3306`，账号密码在各服务的 `config/*.json`
- Redis，默认 `127.0.0.1:6379`，没有密码，配置在 `user-service/config/redis.json`

下面这些不装也能把前面四个服务和支付的 HTTP 端口跑起来：

| 组件 | 不装时会怎样 |
| --- | --- |
| Consul | 自动改用本地 JSON 和 mDNS |
| Jaeger | 追踪器仍会创建，数据没处可看，服务继续跑 |
| Prometheus 服务器 | 订单服务自己在 `127.0.0.1:9092/metrics` 提供数据，没有采集程序也不影响下单代码启动 |
| DTM | 只有“分布式事务”那两个地址会失败：`/addShoppingCart` 和 `/cartAdvanceOrder` |
| 支付宝 / PayPal 外网 | 支付进程仍监听 8086。沙箱密钥失效时，对应接口返回失败说明 |

数据库不用手工建。进程启动时会执行 `CREATE DATABASE IF NOT EXISTS`，再用 GORM 的 `AutoMigrate` 建表。商品库为空时会写入一条示例商品和一个库存 100 的规格。

购物车表放在 `product_center`，和 `product_sku` 同一个库。算总价的 SQL 要 JOIN 这两张表，分成两个库就查不到。

## 6. 启动

先开五个 RPC / 支付进程，再开四个 HTTP 网关。每个命令一个终端，停在那里不要关。

```powershell
cd D:\golang\goshop\user-service
go run .

cd D:\golang\goshop\product-service
go run .

cd D:\golang\goshop\shoppingCart-service
go run .

cd D:\golang\goshop\trade-order
go run .

cd D:\golang\goshop\payment-service
go run .
```

看到 `listening` 之后再开网关：

```powershell
cd D:\golang\goshop\user-service\client
go run .

cd D:\golang\goshop\product-service\client
go run .

cd D:\golang\goshop\shoppingCart-service\client
go run .

cd D:\golang\goshop\trade-order\client
go run .
```

端口对照：

| 进程 | 端口 | 你要用浏览器或 curl 打的 |
| --- | --- | --- |
| 用户 RPC | 8081 | 否 |
| 用户 HTTP | 8088 | 是 |
| 商品 RPC | 8082 | 否 |
| 商品 HTTP | 8087 | 是 |
| 购物车 RPC | 8084 | 否 |
| 购物车 HTTP | 6668 | 是 |
| 订单 RPC | 8085 | 否 |
| 订单 HTTP | 6669 | 是 |
| 支付 | 8086 | 是 |
| 订单指标 | 9092 | 浏览器打开 `/metrics` |
| 购物车熔断监控 | 9096 | 可选 |
| 订单熔断监控 | 9097 | 可选 |

如果日志是 `bind: Only one usage of each socket address`，说明这个端口上一次的进程还在。在任务管理器里结束对应的 `gouser.exe`、`goproduct.exe`、`shoppingCart.exe`、`trade-order.exe`、`payment.exe`、`client.exe`，或者换一个你确认是旧进程的 PID。

MySQL 连不上时，改对应 JSON 的 `user` 和 `pwd`，然后重新 `go run`。`//go:embed` 会在编译时把 JSON 打进程序，所以改完配置必须重新运行，只改文件、不重启是不生效的。

## 7. 亲手调一遍

登录。三个条件必须同时满足：`clientId=0`、`systemId=0`、`verificationCode=6666`。手机号随便填，没有这个号就会插入一行用户。

```powershell
curl.exe "http://127.0.0.1:8088/login?phone=13800000000&clientId=0&systemId=0&verificationCode=6666"
```

成功时 `Code` 是 `SUCCESS`。看返回里的 `user.id`。后面的 `Uuid` 请求头就填这个数字。令牌在 Redis 里放 1 小时。

商品列表、详情、规格：

```powershell
curl.exe "http://127.0.0.1:8087/page?length=10&pageIndex=1"
curl.exe "http://127.0.0.1:8087/showProductDetail?id=1"
curl.exe "http://127.0.0.1:8087/sku?productId=1"
```

加入购物车。`productSkuId` 用上一步返回的 `skuId`。库存会减 1，`shopping_cart` 多一行。

```powershell
curl.exe -H "Uuid: 2" "http://127.0.0.1:6668/increase?number=1&productId=1&productSkuId=1"
```

把 `2` 换成你登录结果里的 `user.id`。不带这个请求头会得到「请在请求头 Uuid 里带上登录返回的用户 ID」。

错误验证码会得到 `TOKEN_FAIL`，这是预期的：

```powershell
curl.exe "http://127.0.0.1:8088/login?phone=13800000000&clientId=1&systemId=0&verificationCode=6666"
```

支付进程起来之后可以访问：

```text
http://127.0.0.1:8086/pagePay?payAmount=0.01&orderNo=测试订单号
http://127.0.0.1:8086/appPay?payAmount=0.01&orderNo=测试订单号
http://127.0.0.1:8086/payPal?amount=1.00&orderNo=测试订单号
```

这三个地址会尝试用浏览器打开收银台。`main.go` 里的支付宝、PayPal 密钥是课程沙箱示例，不能收真实款项，也不要发到公开仓库。支付宝新版要求证书，示例里的公钥字符串加载失败时，日志会写 `alipay ... skipped`，进程仍然继续听 8086。

下单的分布式事务接口是：

```text
GET http://127.0.0.1:6669/cartAdvanceOrder?cartIds=1
请求头 Uuid: 你的用户 ID
```

它要先有 DTM，地址是 `http://127.0.0.1:36789`。没装 DTM 时，这个接口会返回添加失败，购物车和订单的其它能力不受影响。

## 8. 项目里的技术，分别是什么

### Go 模块和工作区

每个服务有自己的 `go.mod`，第一行 `module` 是这个文件夹的名字，别的文件夹用这个名字来 import。`go.work` 把多个模块放在一次编译里。公共库的模块路径是 `git.mashibing.com/msb_47094/shopping-comm`，实际代码在 `goshop/common`。

`replace` 用来把一个导入路径指到本地目录。这里用它补 `go-micro.dev/v4/cmd`：go-micro 4.8 删了这个包，Consul 插件的初始化还在往里面注册，所以 `compat/microcmd` 只放了一个空的注册表。

### embed

`//go:embed config/mysql-user.json` 让编译器把文件收进可执行文件。运行时用 `localConfig.ReadFile` 读出来。这样换一台电脑不用记得把 JSON 拷到某个工作目录，但改配置后要重新 `go run`。

### Gin

HTTP 框架。`r.GET("/login", 处理函数)` 把路径和方法对上。处理函数拿到 `*gin.Context`，可以从查询参数、请求头、JSON 正文里取值，再写出响应。RPC 服务本身不用 Gin，只有 `client` 和支付服务用。

### Protobuf 和 go-micro

`.proto` 用 `message` 描述数据结构，用 `service` / `rpc` 描述能调用的方法。生成代码里有 `RegisterLoginHandler` 这种函数，把你的结构体挂到服务器上。

go-micro 是微服务框架，负责监听、注册、按名字调用。本项目默认传输是 HTTP，日志里是 `Transport [http]`。依赖里能看到 gRPC，那是生成代码和插件带进来的，本机学习时不用单独开 gRPC 端口。

调用是同步的：网关发一次 RPC，等对方返回，再发下一次。`context` 用来传递超时和取消，课程代码里很多地方用的是 `context.TODO()`，表示“先占个位置，以后再补超时”。

### 服务发现：Consul 和 mDNS

Consul 是注册中心，也当配置中心。服务把「我的名字和地址」登记在那里，调用方来查。配置键名在 `common/config.go`：`mysql-user`、`mysql-product`、`mysql-trade`、`redis`。

探测 `127.0.0.1:8500` 失败时，代码不注册 Consul，go-micro 退回 mDNS。mDNS 适合一台电脑上的练习，不适合多台机器的生产环境。

### Viper

读配置的库。它既认识 JSON 文件，也认识 Consul 里的远程 JSON。业务代码只用 `conf.GetString("host")` 这种写法，不关心配置是从文件来的还是从注册中心来的。

### GORM 和 MySQL

GORM 把结构体当成表。`ID` 默认是主键，驼峰字段会变成下划线列名，例如 `ProductId` 变成 `product_id`。`TableName()` 用来指定真实表名，避免 GORM 自作主张加复数。

`AutoMigrate` 会建表、补列，不会删列，也不会改已有数据。手写 SQL 出现在商品详情、规格列表和购物车算价，因为那几处要 JOIN 或 `GROUP_CONCAT`。

分页在 `product_repository.go` 的 `Page`。以前的写法把 `Limit` 写回了共用的 `*gorm.DB`，第一页之后的查询会被旧条件污染。现在每次查询都新开一条链。

### Redis

登录成功后，用户 ID 被当成键，MD5 令牌被当成值，过期时间 1 小时。键不在了就视为未登录。购物车和订单网关每次都会先调用 `GetUserToken`。

课程原来只存二进制形式的键（用户 2 对应 `"10"`）。现在十进制用户 ID 和二进制形式都会写一份，所以请求头填 `2` 或 `10` 都可以。转换函数在 `common/utils.go`，它是教学用的管道示例：一个协程往通道里送字符，另一个协程按 2 的次方还原成整数。不要把它当成通用的 `strconv.Atoi`。

### MD5

`common/md5.go` 用当前时间做登录令牌。MD5 很快，也已经不适合保护密码。这里只是为了把一段字符串变成固定长度的十六进制。正式登录应使用随机令牌，密码应使用 bcrypt 一类算法。

### OpenTracing 和 Jaeger

一次请求穿过网关、商品服务、用户服务时，希望在一张图上看到每一跳花了多少时间。OpenTracing 是写代码用的接口，Jaeger 是收集和展示这些数据的系统。`WrapHandler` 和 `WrapClient` 像洋葱皮，在真正的业务函数外面自动记录开始和结束。

Jaeger Agent 约定在 `127.0.0.1:6831`。没启动时服务照常工作。

### Prometheus

订单服务调用 `PrometheusBoot(9092)`，浏览器访问 `http://127.0.0.1:9092/metrics` 能看到纯文本指标。go-micro 的 prometheus 插件会在有 RPC 之后追加请求次数和耗时。本仓库没有附带 Prometheus 服务器，所以不会有图表，只有这个文本页。

### 限流

购物车和订单的 RPC 套了 uber 的限流器，每秒大约放行 `common.QPS`（100）个请求。超出的请求直接被拒绝，用来在学习环境里认识“保护数据库”这件事。

### Hystrix 熔断

购物车和订单的 HTTP 网关在调用 RPC 时套了熔断器。下游连续失败时，不再每次都傻等，而是快速失败。`9096` 和 `9097` 是熔断器自己的监控流。端口打不开只打日志，不会把业务进程拉倒。

另外还有一个 round-robin 客户端包装：同一个服务如果注册了多个实例，调用会轮流打过去。你现在每个服务只起一份，看不出差别。

### DTM

下单要同时做两件事：把购物车标成已删除，再插入订单。两件事在不同进程、不同数据库里。DTM 的 Saga 模式是：先执行正向接口，失败了再按相反顺序调用补偿接口。

正向和补偿的 HTTP 路径写在网关里：

- 购物车网关 `6668`：`/updateSku` 和 `/updateSku-compensate`，`/addCart` 和 `/addCart-compensate`
- 订单网关 `6669`：`/updateCart` 和 `/updateCart-compensate`，`/addTrade` 和 `/addTrade-compensate`

DTM 服务器要能访问本机的这些地址。`common.CartHTTP` 和 `common.QSBusi` 因此写成了 `127.0.0.1`。

### 支付宝和 PayPal

支付服务不存自己的表。收银台页面由第三方生成，付完款后对方回调本机：

- 支付宝异步通知：`POST /return`
- PayPal 回跳：`GET /payPalBack`

回调里再 RPC 调用 `trade-order`，把 `order_status` 改成 3。订单状态约定是：1 待支付，2 已关闭，3 已支付，4 已发货，5 已收货，6 已完成，7 已追评。

支付宝这段沿用课程，只检查通知正文里有没有支付成功，没有做正式的签名校验。学习调用链可以，不能拿去接真实交易。

### JSON 对拷

`SwapToStruct` 先把一个结构体编成 JSON，再解到另一个结构体。数据库结构和 proto 结构字段对得上，靠的是 `json` 标签，不是内存里的顺序。时间类型对字符串时，对不上的字段会是零值，所以有的详情里时间是 `0001-01-01`。这是这种拷贝方式的限制，不是时间真的丢了。

## 9. 建议阅读顺序

手写的 `.go` 文件用中文注释解释了语法和这一行在业务里的作用。`*.pb.go`、`*.pb.micro.go` 是工具生成的，没有手写注释，阅读时跳过。

按这个顺序打开文件，每一份只回答一个问题。

1. `user-service/proto/user.proto`  
   看 `message` 和 `service`。这是登录的合同。
2. `user-service/main.go`  
   看服务怎么读配置、连数据库、把 handler 注册上去。
3. `user-service/handler/user.go`  
   看一次 RPC 怎么填 `resp`。
4. `user-service/domain/repository/user_repository.go`  
   看登录的三条硬编码条件，以及令牌怎么进 Redis。
5. `user-service/client/user_client.go`  
   看 Gin 怎么把查询参数变成 RPC 请求。
6. `product-service/domain/model/product.go` 和 `product_sku.go`  
   看结构体和表的对应关系。
7. `product-service/domain/repository/product_repository.go`  
   看分页和那条 JOIN SQL。
8. `shoppingCart-service/client/client.go` 的 `/increase`  
   看一次业务如何连续调用三个服务。先看这个函数，不要从头到尾硬读整个文件。
9. `trade-order/domain/repository/trade_repository.go`  
   看订单号怎么拼出来，更新时只改状态。
10. `payment-service/main.go`  
    看支付回调如何找回订单并改状态。
11. `common/config.go`、`utils.go`、`resp.go`  
    看被所有服务引进来的工具。

`*.pb.go` 和 `*.pb.micro.go` 是生成代码，阅读时跳过。改接口要改 `.proto`，再用 `protoc` 重新生成。本仓库没有附带生成命令所需的插件安装步骤，现有生成文件已经够学习调用链。

## 10. 读代码时会反复见到的 Go 写法

- `type IUserRepository interface`：接口。前面的 `I` 是课程命名，Go 社区更常见的是直接叫 `UserRepository`。调用方依赖接口，所以以后可以换成别的数据库实现。
- `func (u *UserRepository) Login(...)`：给结构体定义方法。`u` 是接收者，类似别的语言里的 `this`，只是名字要自己起。
- `func NewUserRepository(...) IUserRepository`：构造函数没有专门关键字，约定用 `New` 开头，返回接口。
- `go func() { ... }()`：启动一个协程。Prometheus 的端口、PayPal 换令牌、熔断器监控页都放在协程里，避免堵住 `main`。
- `defer closer.Close()`：函数退出时一定执行，用来关追踪器。
- `log.Fatal`：打印错误并让进程退出。配置或数据库根本不可用时才会这样，避免带着一个坏连接继续假装服务正常。

## 11. 常见现象

| 现象 | 原因 |
| --- | --- |
| `consul unreachable, use local config` | 正常。本机没开 Consul |
| `jaeger tracer ready` 但 UI 里没有数据 | 正常。没开 Jaeger Agent |
| `alipay app public key skipped` | 正常。示例公钥不是证书，支付进程仍在 |
| `invalid connection` 之后重试又成功 | 本机 MySQL 掐过一条空闲连接。公共库把连接寿命限制成 30 秒，仍建议失败时重试一次 |
| 详情里的时间是 `0001-01-01` | `SwapToStruct` 没把 `time.Time` 对上字符串字段 |
| 加购提示未登录 | 先登录，再让 `Uuid` 等于返回的 `user.id` |
| 下单提示 DTM | 没安装 DTM，或 36789 端口没有进程 |
| 改了 JSON 不生效 | embed 要重新 `go run` |

账号密码、Redis 地址、Consul 地址都集中在 `goshop/common/config.go` 的常量和各服务 `config` 目录。学习时优先改 JSON，不要把地址再写回业务函数里面。
