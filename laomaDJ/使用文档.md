# 老马代驾

乘客端。登录之后可以按一组经纬度询价。

后端是五个 Kratos 服务。本机没有 Consul 时，它们各自监听端口，调用方直连 `127.0.0.1`。下面的登录、询价、司机登记已经在本机跑通。MySQL 账号是 `root` / `root`。

## 1. 这是什么架构

五个服务各自是一个进程。乘客浏览器只访问乘客服务的 HTTP。乘客服务再按名字（或本机端口）调用验证码服务和计价服务。计价服务再调用地图服务。地图服务请求高德的驾车接口。司机端走另一条 HTTP，验证码同样来自验证码服务。

```text
浏览器
  → customer HTTP :8100
      → verifyCode gRPC :9000     要一个 6 位数字
      → valuation gRPC :9300      询价
          → map gRPC :9200        距离和时长
              → 高德驾车接口
```

每个业务服务内部是 Kratos 的四层。目录名在 Go 里叫 package：

```text
HTTP / gRPC
  → service     收请求、填响应
    → biz       业务规则，例如手机号、计价
      → data    MySQL、Redis，以及发出去的 gRPC
```

服务启动时会看 `127.0.0.1:8500`。没有 Consul 时日志是 `consul unreachable, skip register`，调用方改用写死的本机端口。有 Consul 时按服务名发现：`VerifyCode`、`Map`、`Valuation`、`Customer`、`Driver`。这些名字就是各服务 `main.go` 里的 `Name`。

## 2. 目录是干什么的

```text
D:\golang\laomaDJ
├── backend
│   ├── verifyCode     生成验证码            HTTP 8000，gRPC 9000
│   ├── customer       乘客登录、询价        HTTP 8100，gRPC 9100
│   ├── map            高德驾车距离          HTTP 8200，gRPC 9200
│   ├── valuation      按规则算价            HTTP 8300，gRPC 9300
│   └── driver         司机登记、登录        HTTP 8400，gRPC 9400
├── djConsumer         乘客页面，Vue 3
├── driver             只有一行说明，没有页面
├── manager            只有一行说明，没有页面
└── 使用文档.md
```

五个后端各自有 `go.mod`，没有放在同一个 `go.work` 里。在某个服务目录里执行 `go run` 或 `go build`，只用那一个模块。

每个服务里面的文件夹含义相同：

| 目录 | 作用 |
| --- | --- |
| `cmd/<服务>` | `main.go` 读配置、注册服务、监听端口。`wire_gen.go` 是依赖注入生成的组装代码 |
| `configs/config.yaml` | 端口、MySQL、Redis。改完重新运行进程 |
| `api` | `.proto` 合同，以及由它生成的 Go 代码 |
| `internal/service` | 收到请求，填写响应 |
| `internal/biz` | 业务规则 |
| `internal/data` | MySQL、Redis，乘客和司机还在这里调用验证码服务 |
| `internal/server` | HTTP、gRPC 的中间件。乘客和司机的 JWT 在这里 |
| `internal/discover` | 有的服务才有。决定走 Consul 还是直连端口，并缓存 gRPC 连接 |

`helloworld` 和 `Greeter` 是 Kratos 新建项目时的模板，不参与代驾。`third_party` 是 protobuf 的公共定义，不要改。

乘客的业务接口在 HTTP 上。它的 gRPC 端口 `9100` 目前只挂了模板里的 Greeter。验证码、地图、计价的业务接口在 gRPC 上，HTTP 端口主要是模板。司机的业务接口 HTTP 和 gRPC 都有。

## 3. 每种文件是什么

| 文件 | 是什么 |
| --- | --- |
| `.go` | 人写的 Go 源码 |
| `.mod` / `.sum` | 这个服务的模块名和依赖校验和 |
| `.proto` | 人写的接口合同 |
| `.pb.go` | 由 `.proto` 生成的数据结构，不要手改 |
| `_grpc.pb.go` / `_http.pb.go` | 生成的 gRPC、HTTP 注册代码，不要手改 |
| `wire.go` | 人写的依赖关系 |
| `wire_gen.go` | `wire` 命令生成的组装函数，不要手改 |
| `config.yaml` | 端口和数据库 |
| `.vue` / `.ts` | 乘客页面 |

`go.mod` 第一行的 `module` 是这个服务的名字，本服务里的 import 用它。例如乘客服务的模块名是 `customer`。

## 4. 一条询价请求怎么走

```text
浏览器
  |  GET http://127.0.0.1:8100/customer/estimate-price/116.304388,39.984405/116.454406,39.934862
  |  请求头 Authorization: Bearer <登录得到的 token>
  v
乘客 HTTP（Gin 不在这里，是 Kratos 的 HTTP）
  |  中间件先校验 JWT，再比对乘客表里保存的那一张令牌
  |  gRPC Valuation.GetEstimatePrice
  v
计价服务
  |  gRPC Map.GetDrivingInfo
  v
地图服务
  |  GET https://restapi.amap.com/v3/direction/driving
  v
计价服务用城市 1、当前小时的规则算价
  v
JSON 回到浏览器。price 的单位是分
```

登录是另一条链：乘客 HTTP 调用验证码服务拿到 6 位数字，写入 Redis，键是 `CVC:<手机号>`，60 秒过期。登录时比对这个值。手机号还没有乘客记录就插入一行，再签发 JWT。司机的验证码键是 `DVC:<手机号>`，Redis 用的是 2 号库，乘客用 1 号库。

## 5. 环境

需要本机已经有：

- Go 1.21 或更新。各服务 `go.mod` 写的是 1.19，用更新的 Go 可以编译
- MySQL，`127.0.0.1:3306`，账号 `root` / `root`，写在各服务的 `configs/config.yaml`
- Redis，`127.0.0.1:6379`，没有密码

下面这些不装也能把五个进程和前面的接口跑起来：

| 组件 | 不装时会怎样 |
| --- | --- |
| Consul | 日志写 `consul unreachable`，服务之间改用本机端口 |
| Jaeger | 追踪器仍会创建。导出到 `127.0.0.1:14268` 失败只打日志，接口继续 |
| 短信 | 没有短信通道。验证码直接出现在接口响应里，只适合学习 |

数据库不用手工建。乘客、司机、计价三个进程启动时会执行 `CREATE DATABASE IF NOT EXISTS`，再用 GORM 的 `AutoMigrate` 建表。库名是 `laomadj_customer`、`laomadj_driver`、`laomadj_valuation`。验证码和地图不连 MySQL，配置里的 `database` 是模板残留。

计价库为空时会写入城市 1 的三条规则，费用单位是分：

| 小时 | 起步价 | 超出后每公里 | 每分钟 |
| --- | --- | --- | --- |
| 7 点到 23 点前 | 300 | 35 | 10 |
| 23 点到 24 点前 | 350 | 35 | 10 |
| 0 点到 7 点前 | 400 | 35 | 10 |

起步价已经包含 5 公里。公里和分钟都向下取整。不足 5 公里不收里程费，也不会出现负数。

## 6. 启动

先开验证码和地图，再开计价，最后开乘客和司机。每个命令一个终端。配置要用 `-conf`，因为默认路径 `../../configs` 只在 `cmd/<服务>` 那个目录下才指对。

```powershell
cd D:\golang\laomaDJ\backend\verifyCode
go run ./cmd/verifyCode -conf ./configs

cd D:\golang\laomaDJ\backend\map
go run ./cmd/map -conf ./configs

cd D:\golang\laomaDJ\backend\valuation
go run ./cmd/valuation -conf ./configs

cd D:\golang\laomaDJ\backend\customer
go run ./cmd/customer -conf ./configs

cd D:\golang\laomaDJ\backend\driver
go run ./cmd/driver -conf ./configs
```

看到 `[HTTP] server listening` 和 `[gRPC] server listening` 之后再调接口。

| 进程 | HTTP | gRPC | 浏览器或 curl 打的 |
| --- | --- | --- | --- |
| 验证码 | 8000 | 9000 | HTTP 只有模板的 `/helloworld/{name}` |
| 乘客 | 8100 | 9100 | 打 HTTP。9100 上没有乘客业务 |
| 地图 | 8200 | 9200 | 业务在 gRPC。HTTP 是模板 |
| 计价 | 8300 | 9300 | 业务在 gRPC。HTTP 是模板 |
| 司机 | 8400 | 9400 | 打 HTTP |

乘客页面：

```powershell
cd D:\golang\laomaDJ\djConsumer
npm install
npm run dev
```

Vite 默认是 http://127.0.0.1:5173 。先勾选协议，再发送验证码，验证码会填进输入框。登录后进入呼叫页。呼叫页输入框里的是地名，真正拿去询价的是脚本里的两个坐标：`116.304388,39.984405` 和 `116.454406,39.934862`。

如果日志是 `bind: Only one usage of each socket address`，这个端口上一次的进程还在。结束对应的 `verifyCode.exe`、`map.exe`、`valuation.exe`、`customer.exe`、`driver.exe`。

MySQL 账号不对时，改对应 YAML 的 `source`，然后重新运行。乘客、司机、计价三个服务会在连上服务器之后自己建库。

## 7. 亲手调一遍

验证码服务的模板接口，用来确认进程在听：

```powershell
curl.exe "http://127.0.0.1:8000/helloworld/laoma"
```

乘客获取验证码。手机号必须是 11 位大陆号码。成功时响应里的 `verifyCode` 就是验证码，60 秒内有效。`code` 为 `"0"` 表示业务成功。Kratos 使用的 protojson 会把 int64 编成字符串，所以这里的 `code` 和后面的 `price` 都带引号。

```powershell
curl.exe "http://127.0.0.1:8100/customer/get-verify-code/13800000000"
```

格式不对时返回 `电话号码格式错误`：

```powershell
curl.exe "http://127.0.0.1:8100/customer/get-verify-code/12345"
```

登录。把 `verifyCode` 换成上一步返回的数字。请求体是 JSON。手机号第一次出现时会插入一行乘客。

```powershell
curl.exe -X POST "http://127.0.0.1:8100/customer/login" -H "Content-Type: application/json" --data-raw "{\"telephone\":\"13800000000\",\"verifyCode\":\"上一步的验证码\"}"
```

错误验证码返回 `验证码不匹配`。成功时记下 `token`。

不带令牌询价会得到 HTTP 401：

```powershell
curl.exe -D - "http://127.0.0.1:8100/customer/estimate-price/116.304388,39.984405/116.454406,39.934862"
```

带上令牌。这一次会穿过计价和地图，并请求高德。本机实测这对坐标返回过 `price` 为 `1415`，也就是 14.15 元。高德返回的秒数会变，所以金额不会每次相同。

```powershell
curl.exe -H "Authorization: Bearer 你的token" "http://127.0.0.1:8100/customer/estimate-price/116.304388,39.984405/116.454406,39.934862"
```

退出后再用同一张令牌询价，会得到 `登录已失效`：

```powershell
curl.exe -H "Authorization: Bearer 你的token" "http://127.0.0.1:8100/customer/logout"
```

司机。先要验证码，再登录。还没有这行司机记录时，登录会建一条状态为 `stop` 的记录。提交手机号可以重复调用，第二次不会因为唯一索引失败。

```powershell
curl.exe "http://127.0.0.1:8400/driver/get-verify-code/13900000000"
curl.exe -X POST "http://127.0.0.1:8400/driver/login" -H "Content-Type: application/json" --data-raw "{\"telephone\":\"13900000000\",\"verifyCode\":\"验证码\"}"
curl.exe -X POST "http://127.0.0.1:8400/driver/submit-phone" -H "Content-Type: application/json" --data-raw "{\"telephone\":\"13900000000\"}"
```

司机退出用 DELETE，请求头同样是 `Authorization: Bearer`。身份证校验接口会返回 `身份证校验尚未实现`。

乘客令牌的 `jti` 是数字主键。司机令牌的 `jti` 是手机号。两边的签名密钥不同，不能混用。

## 8. 项目里的技术，分别是什么

### Go 模块

每个服务一个模块，import 路径就是模块名，例如 `customer/internal/biz`。五个服务不共用一个 `go.work`。公共的 protobuf 描述在各自的 `third_party` 里各有一份，这是 Kratos 模板的样子。

### Kratos

微服务框架。`kratos.New` 把 HTTP 和 gRPC 两个服务器放进一个进程。配置用 `config.yaml`，结构由 `internal/conf/conf.proto` 生成。`main.go` 里的 `-conf` 指向 `configs` 目录，Kratos 会读这个目录下的 `config.yaml`。

### Wire

`wire.go` 声明谁依赖谁，`wire_gen.go` 是生成出来的 `wireApp`。启动时 `main` 调用它，把配置、数据库、service 组装好。改构造函数的参数后要重新执行 `wire`，只改 `wire_gen.go` 会在下次生成时被覆盖。

### Protobuf、gRPC 和 HTTP

`.proto` 里的 `service` / `rpc` 是能调用的方法。带 `google.api.http` 的方法同时出现在 HTTP 上，例如乘客的 `get: "/customer/get-verify-code/{telephone}"`。没有这条注解的方法只有 gRPC，计价和地图就是这样。

调用是同步的：乘客服务发出询价，等计价服务返回，计价服务中途还要等地图服务。

### 服务发现

Consul 开在 `127.0.0.1:8500` 时，进程把自己的名字和地址登记上去，调用方使用 `discovery:///Valuation` 这种地址。探测失败就不注册，调用方使用 `127.0.0.1:9300` 这类直连地址。连接会缓存在进程里，所以下游重启之后，调用方也要重启，否则会拿到一条已经断开的连接。

验证码服务的元数据里有 `weight: 999`。只有 Consul 开着、并且同一个服务有多份实例时，加权才有意义。本机各起一份，看不出差别。

### JWT

登录成功后用 HS256 签名。乘客密钥在 `customer/internal/biz/customer.go` 的 `CustomerSecret`，有效期 60 天。司机密钥在 `driver/internal/biz/driver.go` 的 `SecretKey`，有效期 30 天。这是学习用的固定字符串，不能拿去保护真实账号。

签名通过之后，中间件还会读取数据库里的令牌。重新登录或退出会改掉这一列，旧令牌因此失效。

### Redis

验证码只放 60 秒。键不在了就视为验证码过期。乘客键前缀 `CVC:`，使用 1 号库。司机键前缀 `DVC:`，使用 2 号库。

### GORM 和 MySQL

结构体上的 `gorm` 标签决定列类型和索引。`gorm.Model` 带上自增主键和 `deleted_at`，所以查询会自动加上“没有删除”。`AutoMigrate` 会建表、补列，不会删列。

姓名、邮箱、微信允许为空，类型是 `sql.NullString`。如果用普通字符串，空串会撞上唯一索引，第二个乘客就插不进去。这些唯一列的长度是 `varchar(191)`，因为 utf8mb4 下一个字符最多 4 字节，191×4 不超过旧版 InnoDB 的 1000 字节索引上限。更长的 `varchar(255)` 会在建表时返回 `Error 1071`。

本机 MySQL 会掐掉空闲连接。连接池把一条连接的寿命限制成 30 秒。计价查询如果仍然遇到 `invalid connection`，会再查一次。

### 高德

地图服务请求 `https://restapi.amap.com/v3/direction/driving`，取第一条路线的 `distance`（米）和 `duration`（秒）。Key 写在 `map/internal/biz/mapservice.go`，是课程示例。HTTP 客户端超时 8 秒。Key 失效或没有路线时，询价会失败，错误会回到乘客接口的 `message`。

### 计价

`GetPrice` 把米换成公里、秒换成分钟，都是整数除法。超出 5 公里的部分乘 `DistanceFee`，分钟数乘 `DurationFee`，再加上 `StartFee`。城市固定为 1，小时用 `time.Now().Hour()`。示例规则每次启动都会按主键覆盖，所以改了那三个数字之后重新运行计价服务即可。

### 验证码算法

`verifyCode/internal/service/verifycode.go` 的 `randCode` 一次取出 63 位随机数，按字符集需要的位数切成多段。数字用 4 位，字母用 5 位，混合用 6 位。切出来的数如果大于等于字符集长度就丢掉，避免用取余时后面的字符被选中的次数更少。随机数来自 `crypto/rand`，多个请求同时要验证码时没有共享的种子。

### Jaeger

乘客、司机、计价在启动时创建 Jaeger 导出器，地址是 `http://127.0.0.1:14268/api/traces`。采集器没开时，日志里会出现连接被拒绝。这不影响接口。

### 跨域

乘客 HTTP 在进入路由之前加上 `Access-Control-Allow-Origin: *`，并直接应答浏览器的 OPTIONS 预检。页面从 `5173` 访问 `8100` 靠的是这个。

## 9. 建议阅读顺序

手写的 `.go` 用中文注释说明这个类型或函数在业务里做什么。`*.pb.go`、`wire_gen.go` 是生成的，阅读时跳过，也不要手改。

1. `backend/customer/api/customer/customer.proto`  
   看乘客有哪些 HTTP 路径。
2. `backend/customer/cmd/customer/main.go`  
   看进程怎么读配置。没有 Consul 时不注册。
3. `backend/customer/internal/server/http.go` 和 `customer.go`  
   看哪些接口要 JWT，令牌怎样和数据库比对。
4. `backend/customer/internal/service/customer.go`  
   看一次请求怎么填响应。
5. `backend/customer/internal/data/customer.go`  
   看验证码进 Redis、乘客进 MySQL、JWT 怎么签发。
6. `backend/customer/internal/discover/dial.go`  
   看直连和 Consul 怎么二选一。
7. `backend/verifyCode/internal/service/verifycode.go`  
   看随机串怎么切出来。
8. `backend/map/internal/biz/mapservice.go`  
   看高德响应里取的是哪两个字段。
9. `backend/valuation/internal/biz/valuation.go`  
   看 5 公里以内为什么不加里程费。
10. `backend/driver/internal/biz/driver.go` 和 `internal/data/driver.go`  
    看司机状态 `stop`，以及重复提交为什么还能成功。

## 10. 读代码时会反复见到的 Go 写法

- `type DriverInterface interface`：业务层只依赖这些方法，测试或换存储时不必碰 MySQL。
- `func (cd *CustomerData) FetchVerifyCode(...)`：给结构体定义方法。`cd` 是接收者，类似别的语言里的 `this`，名字要自己起。
- `func NewCustomerService(...) *CustomerService`：构造函数没有专门关键字，约定用 `New` 开头，交给 wire 调用。
- `func init()` 不适合拿来连数据库。以前乘客的 `migrate.go` 会在 `main` 之前连一次 MySQL，并且用了另一套字段，进程还没读配置就可能退出。建表只留在 `data.NewData`。
- `log` 之后进程继续：Consul 或 Jaeger 不可用时只记一条日志。配置或数据库根本不可用时，`main` 里的 `panic` 会让进程退出，避免带着一个坏连接继续假装服务正常。

## 11. 常见现象

| 现象 | 原因 |
| --- | --- |
| `consul unreachable, skip register` | 正常。本机没开 Consul |
| 日志里 Jaeger `14268` 连接被拒绝 | 正常。没开 Jaeger，接口不受影响 |
| `code` 是 `"0"` 而不是数字 0 | protojson 把 int64 编成字符串。业务成功看这个字符串 |
| 询价 HTTP 401 | 先登录，请求头写成 `Authorization: Bearer <token>` |
| 退出后同一张令牌不能再询价 | 表里的令牌已经清空 |
| `Error 1071` 索引太长 | utf8mb4 的唯一列不要用 `varchar(255)`。乘客表用的是 191 |
| `invalid connection` 之后又成功 | 本机 MySQL 掐过一条空闲连接。计价查询会再试一次 |
| 改了 YAML 不生效 | 配置是进程启动时读的，要重新 `go run` |
| 下游重启后调用方报 EOF | gRPC 连接被缓存了。把调用方也重启 |
| 详情或金额和文档里的 1415 不同 | 高德返回的时长会变。算法没变 |
| 身份证校验返回尚未实现 | 这个接口还没有核验逻辑 |

账号、Redis 地址、端口都在各服务的 `configs/config.yaml`。学习时改 YAML，不要把地址再写回业务函数里面。Consul 地址和直连端口在 `internal/discover/dial.go`，以及地图、验证码的 `main.go`。

## 12. 补上的行程和司机状态

对照表在 `sql/schema.sql`。乘客服务启动时会建 `trip_orders`。询价仍然不写库；乘客确认叫车才插入。

叫车接口和登录、询价一样要带 `Authorization: Bearer <令牌>`。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/customer/trips` | JSON：`origin`、`destination`、`price`。`price` 用询价返回的分。状态变成 `wait_driver` |
| GET | `/customer/trips` | 当前乘客的行程，新的在前 |
| POST | `/customer/trips/move` | JSON：`id`、`status`。只允许待接单到行程中、行程中到完成，或在完成前取消 |

司机状态写在 `drivers.status`。允许的变化在 `driver/internal/biz/status.go`：停用先到收车，再听单，再出车。停用不能直接出车。
