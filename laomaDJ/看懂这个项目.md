# 看懂 laomaDJ

把这个项目看成五个独立进程、一条同步调用链、三张业务表。按下面这些点看，代码就能对上，不必先把 Kratos 或微服务的书读完。

启动、接口和排错仍以 [使用文档.md](使用文档.md) 为准。本文只回答：要懂哪些东西，才算看懂这个项目。

## 先记住项目边界

浏览器只打乘客服务的 HTTP `:8100`。乘客服务再同步调用另外两个进程：验证码走 gRPC `:9000`，询价走计价 `:9300`，计价再问地图 `:9200`，地图去调高德。司机是另一条 HTTP `:8400`，验证码仍来自同一个验证码服务。

```text
浏览器
  → customer HTTP :8100
      → verifyCode gRPC :9000     要一个 6 位数字
      → valuation gRPC :9300      询价
          → map gRPC :9200        距离和时长
              → 高德驾车接口

司机浏览器
  → driver HTTP :8400
      → verifyCode gRPC :9000
```

每个进程内部都是同一套四层：

```text
HTTP / gRPC
  → server     收请求，乘客和司机在这里校验 JWT
    → service  填响应
      → biz    业务规则
        → data MySQL、Redis，以及发出去的 gRPC
```

`cmd/<服务>/main.go` 只负责读配置和启动。`wire.go` 只是告诉生成器怎么把这四层拼起来，运行时执行的是 `wire_gen.go`。

五个目录各有一个 `go.mod`。`go run`、`go test`、`go mod tidy` 都在对应服务目录里做：

```text
backend/verifyCode
backend/customer
backend/map
backend/valuation
backend/driver
```

`*.pb.go`、`*_grpc.pb.go`、`*_http.pb.go`、`wire_gen.go` 是生成的，阅读时跳过。名叫 `Greeter`、`helloworld` 的文件是 Kratos 模板，不参与代驾。

## 看懂代码所需要的东西

按这个顺序就够。每一项都只要懂到「能解释这个项目里的那一处」。

### 1. Go 里这几种写法

结构体方法、接口、`NewXxx` 构造函数、返回 `(结果, error)`。乘客和司机的 `biz` 只依赖接口，MySQL 在 `data` 里实现，所以测试可以不连数据库。

`sql.NullString` 要认得：姓名、邮箱、微信允许为空。如果用普通字符串，空串会撞上唯一索引，第二个乘客就插不进去。

### 2. Protobuf 怎么同时变成 HTTP 和 gRPC

打开 `backend/customer/api/customer/customer.proto`。带 `google.api.http` 的方法会出现在 `:8100`，例如获取验证码、登录、询价、叫车。计价和地图的 proto 没有这条注解，所以它们只有 gRPC，浏览器打不了 `:9300`。

### 3. 两条真实链路

登录：

1. 乘客 HTTP 向验证码服务要 6 位数字。
2. 写入 Redis 键 `CVC:<手机号>`，60 秒过期。
3. 登录时比对这个值。
4. 手机号第一次出现就插入 `customers`，再签发 JWT。

询价：

1. 中间件先验 JWT，再比对乘客表里保存的那一张令牌。
2. gRPC 到计价。
3. 计价再 gRPC 到地图，地图请求高德。
4. `price` 的单位是分。

司机验证码键是 `DVC:<手机号>`，放在 Redis 2 号库。乘客用 1 号库。

### 4. JWT 为什么退出后旧令牌不能用

签名只证明令牌是这个进程签发的。

- 乘客密钥在 `customer/internal/biz/customer.go` 的 `CustomerSecret`，有效期 60 天。
- 司机密钥在 `driver/internal/biz/driver.go` 的 `SecretKey`，有效期 30 天。
- 两边不能混用。乘客令牌的 `jti` 是数字主键，司机的 `jti` 是手机号。

签名通过之后，中间件还要读数据库里的 `token` 列。重新登录或退出会改掉这一列，所以未过期的旧令牌也会失效。

### 5. 服务之间怎么找到对方

看 `internal/discover/dial.go`。

- 本机 `8500` 上有 Consul，就按名字发现，例如 `discovery:///Valuation`。
- 没有 Consul，就直连 `127.0.0.1:9300` 这类端口。

连接缓存在进程里。下游重启后，调用方也要重启，否则会用到一条已经断开的连接。日志里的 `consul unreachable` 和 Jaeger `14268` 连接失败都是正常的，接口照常工作。

### 6. 三张表和两个状态机

库是启动时自己建的：`laomadj_customer`、`laomadj_driver`、`laomadj_valuation`。列注释在模型的 `gorm` 标签上。软删除看 `deleted_at`。

计价规则按当前小时选城市 1 的一行。起步价含 5 公里，超出部分才乘每公里费用，公里和分钟都向下取整。询价不写库。

确认叫车才插入 `trip_orders`。状态只允许「待接单 → 行程中 → 完成」，完成前可以取消。

司机新登记是 `stop`。只允许「停用 → 收车 → 听单 → 出车」，停用不能直接出车。规则在 `driver/internal/biz/status.go`。

### 7. 乘客页面只是上面那条 HTTP 的调用方

`djConsumer` 是 Vue 3。登录后进入呼叫页。输入框里的地名不参与计算，真正拿去询价的是脚本里写死的两个坐标：`116.304388,39.984405` 和 `116.454406,39.934862`。

## 建议顺着这 10 个文件读

手写的 `.go` 用中文注释说明这个类型或函数在业务里做什么。

1. `backend/customer/api/customer/customer.proto`：乘客有哪些 HTTP 路径。
2. `backend/customer/cmd/customer/main.go`：进程怎么读配置。没有 Consul 时不注册。
3. `backend/customer/internal/server/http.go` 和同目录的令牌校验：哪些接口要 JWT，令牌怎样和数据库比对。
4. `backend/customer/internal/service/customer.go`：一次请求怎么填响应。
5. `backend/customer/internal/data/customer.go`：验证码进 Redis、乘客进 MySQL、JWT 怎么签发。
6. `backend/customer/internal/discover/dial.go`：直连和 Consul 怎么二选一。
7. `backend/verifyCode/internal/service/verifycode.go`：随机串怎么切出来。
8. `backend/map/internal/biz/mapservice.go`：高德响应里取的是哪两个字段。
9. `backend/valuation/internal/biz/valuation.go`：5 公里以内为什么不加里程费。
10. `backend/driver/internal/biz/driver.go`、`status.go` 和 `internal/data/driver.go`：司机状态 `stop`，以及重复提交为什么还能成功。

自测不连数据库：

```powershell
cd D:\golang\laomaDJ\backend\customer
go test ./internal/biz/

cd D:\golang\laomaDJ\backend\driver
go test ./internal/biz/

cd D:\golang\laomaDJ\backend\verifyCode
go test ./internal/service/
```

## 可以先放着的

Consul 加权、Jaeger 采样、高德 Key 的申请流程、身份证校验。身份证那个接口会直接返回「尚未实现」。验证码没有短信通道，数字就在接口响应里。
